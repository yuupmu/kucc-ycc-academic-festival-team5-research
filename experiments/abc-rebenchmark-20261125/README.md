9개 초안에서 독립 감시자 C는 첫 수정 251/360, 추가 수정 후 246/360이었다. 자체 검토 B는 각각 246/360, 247/360이었고 메인 단독 A는 246/360이었다. 같은 9쌍의 최종 점수에서 C는 B 대비 2승 5무 2패였다.

이전 실행의 최종 합계는 A 246점, B 246점, C 251점이다. 이전에는 한 번만 수정했다. 이번에는 담당자가 의견 본문까지 읽고 답변을 의견별로 연결했으며, 확정 검사 실패 시 재수정도 허용했다. 이전 대비 점수 변화에는 이 변경들이 함께 반영된다.

## 결과를 바꾼 세 사례

- 14B 시드 43에서 C는 정식 질문 칸이 모두 비어 있었지만, 의견 본문이 일반 마감 뒤의 정정 허용 여부를 짚었다. C는 첫 수정에서 20점에서 25점이 됐고 B는 최종 20점이었다. [C의 검토와 제출](14b-seconds-43-C.json)
- 7B 시드 17에서 C는 첫 수정 20점에서 추가 수정 5회 뒤 24점이 됐다. 같은 초안을 쓴 B도 5회 더 수정했지만 20점에 머물렀다. [시드 17의 C 실행](7b-seconds-17-C.json)
- Qwen3 시드 43에서 C의 첫 수정은 39점이었다. 재수정하면서 시작 정각 거부는 고쳤지만, 일반 마감 이후 분기에 항상 참인 조건 `until_start_seconds < 0 or until_start_seconds >= 0`을 넣었다. 정당한 정정까지 거부해 기존 정답 10개를 잃었고, 5회 한도에서 30점·미해결로 끝났다. 최종 점수에는 미해결 실행의 마지막 제출도 포함했다. [시드 43의 C 실행](qwen3-8b-off-43-C.json)

이전에 같은 Qwen3 사례를 따로 재실행했을 때에는 40점이었다. 두 실행의 초안, 세 검토 원문, 첫 수정 코드는 같았다. 이전에는 세 번째 의견의 담당자 답을 비웠고, 이번에는 그 의견이 정정 시간 적용 여부를 지적했다고 읽어 같은 10분 규칙을 다시 연결했다. 재수정 때 메인이 본 입력이 달라졌다. 이 차이 하나가 점수 차이의 원인인지는 이번 실험만으로 판별하기 어렵다. [이전 단건 실행](../abc-delivery-check/README.md)

## 실행 조건과 원본

모델마다 A에서 질문·초안을 새로 만들고 B·C에 똑같이 전달했다. 세 조건을 합쳐 초안 9개와 결과 27개다. B는 이전 자체 검토를 보며 세 관점을 순서대로 검토하고 C는 같은 초안을 각자 검토한다. 검토 원문과 담당자 답 54쌍이 메인의 실제 첫 수정 요청에 그대로 포함됐는지 검사했다. 이전 실행과 코드가 일치한 A 초안은 9/9개였다.

Codex가 진행자 역할을 맡아 기존 고정 답변 카드를 적용했다. 실제 질문 또는 의견에 나타난 판단에만 답했고, 칭찬만 있는 의견에는 빈 답을 허용했다. 이전 검토 자료에서 분류한 답은 초안 대화와 세 검토 원문이 모두 같은 경우에만 적용했다. 일치한 묶음은 18/18개다.

온도 0.3, top-p 0.9, top-k 40, 질문/검토/코드 출력 상한 450/320/1,500토큰을 사용했다. Qwen3의 추론 모드는 껐다. 기존과 동일하게 로컬 서버 슬롯 한 개에서 호출했고 B·C 순서는 모델·시드별로 번갈아 배정했다.

실제 모델 호출 121회, 사용 토큰 160,866개, 전체 경과 19분 3.1초였다. 이 합계에서 공통 초안 생성은 한 번만 센다. 전체 시간에는 모델 로딩·교체, 담당자 처리, 채점이 포함된다.
