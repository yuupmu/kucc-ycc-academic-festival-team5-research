## 이전 실험에서 확인한 병목

최근 구조는 메인 초안 → A·B·C 독립 검토 → D의 의견 통합 → 메인 수정이었다. 초기 A는 개입 필요성, B는 근거, C는 사람의 판단이 필요한 부분을 검토했다. 앞선 보고서에서 **실험 조건**을 A(단독)·B(자체 검토)·C(독립 검토)로 부른 것과 여기서의 **역할 이름**은 구분한다. [기존 세 조건의 비교](../abc-rebenchmark-20261125/README.md)

- 부분정보로 시작한 세 시드의 메인은 85/120점이었다. 첫 검토가 95/120점으로 올렸지만 상승분 전부가 시드 17에서 나왔다. 2·3회차에 32,712토큰을 더 사용해도 120개 판정 모두 그대로였다. 시드 29에서는 일반 마감 이후 바로 거부해 정정 예외에 도달하지 못했다. 시드 43에서는 앞에서 24시간 이상 남으면 이미 허용한 뒤 25시간 이상인지를 다시 검사했다. [회차별 실행 기록](../qwen3-review-cycles-20261125/README.md)
- D에게 첫 반환을 추적하라고 지시해도 두 실패 코드에서 요약 조건과 같은 최종 코드가 나왔다. 후속 비교에서 D의 허용·거부 예측은 동료 의견을 보거나 가리거나 9/18이었다. D가 정확한 실행값을 메인에게 보장할 수 없었다. 또한 원래 회차 실행기는 질문이 있으면 같은 감시자의 피드백 칸을 비웠다. 원문이 모두 전달된 실험에서도 코드 판독 오류는 남았다. [D의 요약·추적 비교](../qwen3-editor-replay-20261125/README.md) · [동료 의견 유무 비교](../qwen3-editor-opinions-20261125/README.md)
- 고객 안내문으로는 정정 시간이 있다는 점만 알 수 있다. 정확히 몇 분이고 경계를 포함하는지는 별도 운영 명세에 나온다. 코드의 실제 반환을 확인해도 누락된 정책 수치까지 알아낼 수는 없다. 이 영향을 따로 보기 위해 두 정보 조건을 유지했다. [완전정보 단일 모델 기준선](../full-information-single-20261125/README.md)

## 조정한 실행 방식

1. 공통 초안을 격리된 Python에서 실행한다. 부분정보 조건은 고객 안내문에서 도출한 네 가지 예시를 사용한다. 예를 들어 이용까지 6시간으로 고정하고, 3일 전 예약과 방금 만든 예약을 비교한다. 완전정보 조건은 공개한 운영 명세에 따라 마감 정각, 정정 시간 경계, 이용 시작 우선순위 등 다섯 검사를 추가한다. 초안이 해당 검사를 전부 통과하면 검토 호출을 생략한다.
2. 실패가 있으면 A는 두 입력의 차이, B는 분기와 반환, C는 확정된 규칙·가정과 기존 동작 보존을 검토한다. 세 역할은 동료의 의견을 보지 않는다. D가 이를 통합한다. 실행기는 D의 요약과 별도로 실제 실행 표, 세 사람의 질문과 피드백 전문을 메인에게 전달한다.
3. 메인은 한 번 수정한다. 기존에 통과한 공개 검사를 모두 보존하고 적어도 하나를 새로 통과한 수정만 채택한다. 첫 시드의 검토에서 오래된 예약을 고치면서 방금 만든 예약을 거부하기 시작한 사례가 있어, 비공개 점수를 보기 전에 한 번의 추가 수정 규칙을 정했다. 채택한 함수에 실패가 남아 있으면 메인에게 각 입력의 기대값·실제값을 명시한 검사식과, 한 인자만 다른 대조 사례를 보낸다. 같은 채택 기준을 다시 적용하고 종료한다. 첫 수정의 기각 기록 (로컬 보관 자료) · 추가 수정 조건 (로컬 보관 자료)

## 비교 설계와 해석 범위

| 조건 | 초안 이후 허용한 호출 |
|---|---|
| 단독 제출 | 추가 호출 없음 |
| 짧은 자체 검토 | 메인이 실행 표로 한 번 수정, 실패가 남으면 메인 추가 수정 최대 1회 |
| 순차 자체 검토 | 같은 개발자가 앞선 자기 의견을 보며 세 관점을 검토하고 요약한 뒤 수정, 추가 수정 최대 1회 |
| A·B·C·D | 독립 검토 3회, D 요약 1회, 메인 수정 1회, 추가 수정 최대 1회 |

각 행은 같은 Qwen3-8B Q4_K_M, 추론 끔, 온도 0.3, top-p 0.9, top-k 40을 사용한다. 같은 정보 조건·시드의 네 방식은 새로 생성한 초안 하나를 공유한다. 순차 자체 검토와 A·B·C·D의 역할별 출력 상한은 각각 320·320·320·800·1,500토큰으로 동일하다. 검토 세 조건의 공개 검사, 수정 채택 기준, 추가 수정 기회도 같다. 시드별로 조건 실행 순서를 순환했다. 직접 제출에는 검사 결과를 전달하지 않는다.

기존 시드 17·29·43과 추가 시드 71·89·113에 대해 같은 40문항을 사용했다. 추가 시드는 생성의 변동성을 살피기 위한 것이다. 모든 조건에서 비공개 채점 사례·정답·중간 점수는 모델 입력에서 제외했다. 점수 차이에는 실행 근거, 역할별 검토 지시, 원문 전달, 수정 채택 방식이 함께 작용할 수 있다. 실험 설계와 공개 검사 (로컬 보관 자료) · [실행 코드](../verified_cycles.py)

기존 문항에만 맞는 수정을 구분하기 위해 예약 경과 시간 8개와 시작까지 남은 시간 7개를 교차한 별도 56쌍도 최종 제출 고정 후 채점했다. 56쌍은 공개 검사 및 기존 40문항의 입력 쌍과 겹치지 않는다. 판정식은 기본 운영 명세에서 도출하고 기존 40문항의 정답과 전부 일치하는지 대조했다. 이 추가 평가는 같은 정책 안에서 입력 범위가 바뀔 때의 결과를 측정한다. [별도 평가 입력과 판정식](../cancellation_transfer.py)

비용은 각 조건을 단독으로 실행했을 때의 합계다. 공통 초안 비용을 각 조건에 한 번씩 포함한다. A·B·C는 각각 독립된 입력을 받으며 로컬 모델 한 개가 차례로 처리한다. 모델 시간은 서버 응답 대기 시간의 합으로, 채점·검사·모델 로딩 시간은 제외한다.
