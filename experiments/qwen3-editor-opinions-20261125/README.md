# 감시 의견이 Qwen3 검토자 D의 코드 추적에 미치는 영향

감시 의견을 가렸을 때와 보여줬을 때 D가 예측한 허용·거부는 18쌍에서 모두 같았다. 정확도는 두 조건 모두 9/18이었다. 줄과 반환값을 함께 맞힌 경우는 의견을 가렸을 때 0/18, 보여줬을 때 2/18이었다. 두 코드에서는 감시 의견을 제거해도 기존 코드의 실행 경로를 읽는 문제가 남았다.

| 측정 항목 | 감시 의견 가림 | 감시 의견 제공 |
| --- | ---: | ---: |
| 첫 반환 줄과 반환값 모두 정확 | 0/18 | 2/18 |
| 허용·거부 값 정확 | 9/18 | 9/18 |
| 정정 조건 삭제가 판정을 바꾸지 않는다고 선택 | 6/6 | 6/6 |
| 삭제가 판정을 바꾸지 않는 이유도 정확히 설명 | 0/6 | 0/6 |
| D의 입력·출력 토큰 합계 | 6,452 | 8,854 |
| D의 응답 시간 합계 | 20.09초 | 24.03초 |

### 어떤 입력에서 틀렸나

각 칸의 점수는 세 생성 시드 중 반환값 자체를 맞힌 횟수다. 정답 줄 번호는 D에게 제시한 코드에 대응한다.

| 코드 | 입력 | 실제 실행 | 의견 가림 | 의견 제공 |
| --- | --- | --- | ---: | ---: |
| 29 | P · 이용까지 50분 | 15줄에서 거부 | 0/3 | 0/3 |
| 29 | Q · 이용까지 25시간 30분 | 26줄에서 허용 | 3/3 | 3/3 |
| 29 | R · 이용 시작 60초 후 | 15줄에서 거부 | 3/3 | 3/3 |
| 43 | P · 이용까지 50분 | 34줄에서 거부 | 0/3 | 0/3 |
| 43 | Q · 이용까지 25시간 30분 | 21줄에서 허용 | 0/3 | 0/3 |
| 43 | R · 이용 시작 60초 후 | 17줄에서 거부 | 3/3 | 3/3 |

- **코드 29.** P는 24시간 미만이라 15줄에서 바로 거부된다. 두 조건의 D 모두 세 번 다 허용이라고 답했다. 반면 Q는 두 조건 모두 반환값을 맞혔다. 여기서만 의견을 본 응답 2개가 26줄도 맞혔고, 의견을 가린 응답은 세 번 모두 바로 위 주석인 25줄을 골랐다.
- **코드 43.** Q는 24시간 이상이므로 21줄에서 허용된다. 여섯 응답 모두 마지막 34줄에서 거부된다고 예측했다. R은 여섯 응답 모두 거부를 맞혔으나, 실제 반환문인 17줄 대신 조건문인 16줄을 골랐다. 따라서 줄 번호만으로 추론 능력을 평가하면 같은 분기를 찾아간 답까지 틀린 것으로 센다. 허용·거부 점수를 함께 제시한 이유다.
- **일반화 질문.** 두 코드 모두 앞선 조건이 정정 분기의 모든 후보를 이미 처리한다. 12번 모두 삭제 효과가 ‘없음’을 선택했지만 어느 설명도 이 관계를 밝히지 못했다. 예를 들어 코드 43·생성 시드 29에서 의견을 본 D는 25시간 남은 경우 삭제하면 거부로 바뀐다고 설명했다. 실제로는 24시간 이상 조건에서 여전히 허용된다. 선택지만 집계하면 이 오류가 사라진다. 해당 응답 (로컬 보관 자료)

### 해석과 범위

감시 의견을 없앴을 때도 동일한 입력에서 동일한 반환값 오류가 반복됐다. 이 두 코드에서 관찰한 오류에는 잘못된 동료 의견이 필수 원인이 아니었다. 현재 Qwen3-8B Q4_K_M, 추론 끔, 사용한 지시와 응답 양식의 조합에서 D는 실제 동작을 일관되게 파악하지 못했다. 같은 두 코드에서 시드만 반복한 결과이므로 모델 일반의 한계나 다른 모델과의 격차는 추정할 수 없다. 정확한 진단을 받은 메인의 수정 능력도 이 실험에서는 측정하지 않았다.

입력별 판정·근거·토큰·시간 (로컬 보관 자료) · [실험 실행 코드](../editor_opinions.py)

## 실험 설계

일반 취소 마감 뒤 정정 예외가 작동하지 않았던 두 수정 전 코드(기존 시드 29의 2회차 입력, 43의 3회차 입력)를 사용했다. 이번 실험 단위는 D의 응답이다. 메인 수정이나 예약 정책 벤치마크 채점은 포함하지 않았다.

- **조작변인.** D에게 해당 코드의 A·B·C 질문과 피드백 원문을 보여주거나, 같은 입력의 감시 의견 칸을 빈 목록으로 보냈다. 코드 29에 대해 감시자 A가 든 예시는 양쪽에 동일하게 주었다.
- **고정 조건.** 공개 과제, 원래 코드와 주석, 줄 번호, 입력 세 개와 순서, 시스템 지시, 응답 양식, 각 쌍의 생성 시드를 고정했다. Qwen3-8B Q4_K_M, 추론 끔, 온도 0.3, top-p 0.9, top-k 40, 응답 상한 800토큰이다. 각 응답은 독립된 대화이며 조건 순서는 번갈아 배치했다.
- **반복.** 코드 2개 × 생성 시드 3개(17·29·43) × 의견 조건 2개로 총 12회 호출했다. ‘코드 29·43’은 저장된 코드의 출처이고 ‘생성 시드’는 이 실험의 응답 생성 설정이다.
- **입력.** 세 사례 모두 예약한 지 100초다. P는 이용까지 3,000초(50분), Q는 91,800초(25시간 30분), R은 이용 시작 60초 후다. 함수의 실제 동작을 묻기 위해 정한 입력이다.
- **1차 지표.** D가 입력별로 보고한 첫 `return` 줄과 반환값이 모두 맞으면 1점이다. 반환값만 맞힌 비율도 별도로 집계한다. 모델 응답 12개를 모두 저장한 뒤에만 원본 파이썬 함수를 실행하고 인터프리터가 기록한 반환 위치·값과 대조한다. 비공개 정책과 가채점은 D에 전달하지 않는다.
- **2차 지표.** 정정용 조건을 삭제하면 어느 유효한 입력에서라도 반환값이 바뀔 수 있는지 묻는다. 두 코드 모두 정답은 ‘없음’이다. 정답 선택과, 앞선 조건 때문에 정정 분기에 도달할 수 없다는 올바른 근거 제시는 따로 집계한다.

직전 실험과 달리 두 조건 모두 실행 줄을 특정하는 질문과 구조화된 답안 양식을 사용했다. 직전 실험과의 정확도 차이만으로 그 양식의 효과를 추정할 수 없다. 조건별 판정 18개는 두 코드에 같은 입력 세 개를 세 번 반복한 결과다.
