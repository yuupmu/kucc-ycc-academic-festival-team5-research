# A·B·C 검토가 점수를 바꾼 경우와 바꾸지 못한 경우

독립 감시자 3명을 붙인 C는 9개 초안 중 8개에서 40문항의 판정을 하나도 바꾸지 못했다. 메인 자체 검토 B는 9개 모두 같았다. C의 유일한 변화는 14B 시드 43에서 오답 10개를 고치고 기존 정답 5개를 잃은 것이다. [실험 조건과 시간·토큰](README.md)

| 초안 A와 대조한 항목 | B 자체 검토 | C 독립 감시 |

| 제출 코드 문자열까지 일치 | 6/9 | 7/9 |

구문 트리가 달라져도 이 평가의 입력에서 결과가 같을 수 있다. 두 조건 모두 검토 27회와 최종 수정 9회가 정상 종료됐다. 출력 상한에 걸린 응답이나 최종 채점 중 실행 오류는 없었다.

## 질문과 파이프라인의 영향

7B와 14B의 C 검토 18건에서 공식 질문 칸은 모두 비었다. 의견 본문에 적힌 확인 요청은 메인에게 전달됐지만 운영자에게 접수되는 경로는 질문 칸뿐이었다. B는 9개 시드·모델 조합 중 3개에서 세 의견의 피드백 문장이 완전히 같았다. 특히 14B 시드 29의 B는 코드 첫 조건에 이미 있는 10분 유예가 빠졌다는 주장을 세 번 반복했다. 정식 질문 칸의 제출 18건에도 이런 반복이나 수정 지시가 포함된다. [14B 시드 29](14b-seconds-29-B.json)

이번 비교에서는 한 초안에 세 의견과 담당자 답을 모아 메인에게 주고 한 번 수정한 다음 채점했다. 검토 중 제안한 반례를 실행하거나 수정 실패를 다시 보여 주는 단계는 없었다. 웹 실행기에 도입한 반복 검증을 적용한 결과와는 구분해야 한다. 별도의 기존 재시도 비교에서는 Qwen3 시드 43이 실패 입력을 반복해서 봤을 때 네 번째 수정에서 정각 오류를 고쳤다. [이번 실행 코드](../timed_abc.py) · [기존 재시도 비교](../pilot-qwen/three-monitors/completion-gate/README.md)

같은 모델에 세 가지 관점을 주면 비슷한 오류를 놓칠 수 있다는 해석은 로그와 맞는다. 그 원인이 모델 공유인지, 검토 지시인지, 한 번뿐인 수정 기회인지는 이번 A·B·C만으로 각각 추정할 수 없다. 이 분석은 기존 실행의 저장된 응답·코드·문항별 판정에 근거했다. 예시 입력은 분석 시점에 저장된 코드로 재현했으며 모델에는 추가 입력을 주지 않았다.
