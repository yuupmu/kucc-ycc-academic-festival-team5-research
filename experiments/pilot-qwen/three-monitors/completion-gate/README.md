# 담당자 답변을 매번 검사하면 시작 정각 오류가 고쳐지는가?

**Qwen3-8B의 시드 43에서 고쳐졌다.** 담당자가 “이용 시작 시각과 같거나 이후면 거부”라고 답했던 실행이다. 같은 초안에서 실패한 입력·기대값·실제값을 돌려주자 네 번째 추가 수정에서 시작 정각을 거부했고 39/40에서 40/40이 됐다. 일반 재검토 대조군은 다섯 번 수정한 뒤에도 39/40이었다. 웹 실행기에서는 검사 0건을 여섯 번 연속 제출하면 ‘미검증’으로 일시 정지했다. 피드백을 받은 실행 (로컬 보관 자료) · 대조군 (로컬 보관 자료) · 웹의 검사 0건 재현 (로컬 보관 자료)

## 세 모델에서 나타난 변화

점수는 같은 예약 취소 40문항을 시드 17·29·43에서 평가한 정답 수다. 이번 비교는 이전 실험에서 감시 의견, 담당자 답변, 공개 사례와 초안의 실행 결과까지 본 메인이 제출한 코드를 출발점으로 삼았다. 공개 검사가 남아 멈춘 제출도 마지막 코드를 별도로 채점했다. ‘완료’는 해당 시드에 공개된 검사를 모두 통과했다는 뜻이다. [이전 실험](../monitor-pipeline-report.ko.md) · 시드별 집계와 문항 변화 (로컬 보관 자료)

- **7B**는 대조군 대비 오답 15개를 고치고 기존 정답 11개를 잃었다. 시드 29는 20→29였고 시드 43은 30→25였다. 세 제출 모두 확정된 검사 중 적어도 하나를 계속 틀려 완료를 보류했다.
- **14B**는 첫 수정에서 피드백 조건이 79/120, 대조군이 74/120이었지만 마지막에는 두 조건의 문항별 판정이 모두 같았다. 두 조건 모두 공통 출발점보다 5개 낮았다. 추가 수정이 기존 동작을 해칠 수 있음을 보여 준다.
- **Qwen3**는 시드 17에서 두 조건 모두 20/40으로 멈췄다. 시드 29의 출발 코드는 공개 검사 5/5를 통과해 두 조건 모두 재시도 없이 종료했고 전체 점수는 39/40이었다. 달라진 시드는 43 하나였다.

## 웹 파이프라인에 적용한 변경

1. **검사 0건은 미검증이다.** 현재 코드 버전에 대해 메인, 감시자, 담당자 확정 사례가 실제로 실행됐는지 확인한다. 한 건 이상 실행하고 모두 통과해야 완료할 수 있다. 수정 한도까지 실패하거나 계속 0건이면 마지막 코드와 검사 결과를 남기고 멈춘다.
2. **기본 예약 취소 과제에서 담당자 답과 검사 사례를 연결한다.** 기존 운영자 카드의 확정 문구는 실행 사례로 변환한다. 자유 서술로 새 정책을 정하면 담당자가 사례를 보충할 수 있다. 행동 변경이 없는 설명은 맥락으로 표시할 수 있다. 이후 코드가 바뀔 때마다 해당 결정들을 다시 검사한다. 메인이 정책을 맥락으로 분류했거나 한 번 반영했다고 보고해도 확정된 검사가 실패하면 완료되지 않는다.
3. **다음 수정과 화면에서 실패 근거를 볼 수 있다.** 메인에게 입력·기대값·실제값과 해당 답변의 ID를 돌려준다. 화면에서도 미검증·실패·통과를 구분하고 실패한 입력과 결과를 펼쳐 볼 수 있다. [실행 로직](../../../../backend/live_workflow.py) · [답변에서 검사 사례를 만드는 규칙](../../../../backend/decision_checks.py)

이전과 동일한 ‘항상 거부’ 코드와 세 감시자의 ‘계속 진행’ 고정 응답을 실제 웹 백엔드에 넣었다. 이전에는 0/0으로 완료됐고 이번에는 0/0 미검증으로 일시 정지했다. 이어 Qwen3의 실제 수정 코드들을 같은 순서로 웹 백엔드에 재생했다. 담당자 응답 후 7/8인 동안 수정을 계속했고 8/8이 된 버전에서 완료했으며 별도 채점은 40/40이었다. 웹 재생은 저장된 출력을 사용했다. 모델이 새로 답한 결과는 위 로컬 비교에서 측정했다. 이전 웹 기록 (로컬 보관 자료) · 변경 후 웹 기록 (로컬 보관 자료) · Qwen3 웹 재생 (로컬 보관 자료)

## 무엇을 통제했나

모델 파일과 양자화, 추론 모드, 시드, 과제, 원래 대화, 최초 코드, 감시자 3명의 의견, 담당자 답, 공개 검사와 40문항 채점기를 고정했다. 모델이 다시 질문하거나 감시자를 재호출하지 않았다. 두 조건 모두 같은 지시로 재검토하고, 실패 사례 조건만 직전 실행의 실패 내역과 이를 수정하라는 안내를 추가했다. 각 시드에서 처음부터 공개 검사를 통과했으면 두 조건 모두 건너뛰었고, 나머지는 같은 실행기에서 한 번에 최대 1,500 출력 토큰, 최대 5회 추가 수정을 허용했다. 양쪽 모두 첫 공개 검사 통과 시 멈췄다. 따라서 대조 비교가 측정하는 것은 **재시도 기회가 동일할 때 실패 정보를 제공하는 효과**다. 빈 검사로 완료하는 문제는 웹에서 별도로 검증했다.
