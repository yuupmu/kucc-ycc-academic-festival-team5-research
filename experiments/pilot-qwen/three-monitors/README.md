# 감시자 3명이 예약 취소 코드에 미친 영향

세 모델의 최종 비교, 감시자가 제안한 테스트의 정확도, 확정된 규칙으로 재실행한 결과와 웹 실행기 완료 판정은 [감시자·파이프라인 실험 보고서](monitor-pipeline-report.ko.md)에 정리했다. [모델·시드별 집계](paired-results.json)에서 문항 변화와 토큰 수를 확인할 수 있다.

완료 조건을 수정한 뒤 같은 제출에서 재검토를 반복한 후속 결과는 [완료 조건 변경 후 통제 실험](completion-gate/README.md)에 있다.

## 어느 단계에서 실패했나

- **오류 발견.** 7B의 시드 43 초안에는 일반 마감 전 취소를 허용하는 분기가 빠져 있었다. 세 감시자는 초안이 조건을 충족한다는 취지로 답했다. 메인은 같은 코드를 제출했다.
- **운영자에게 질문 전달.** 7B와 14B의 독립 감시자들은 공식 질문 칸을 한 번도 채우지 않았다. 14B의 일부 감시자는 의견 칸에서 정책을 확인해 달라고 했다. 메인은 의견 전체를 받았고, 담당자는 제출된 질문만 받았다.
- **답변을 코드에 반영.** Qwen3 시드 43의 감시자는 정정 시간이 이용 중에도 적용되는지 정확히 물었다. 운영자가 시작 순간부터 거부한다고 답했지만, 메인의 최종 조건은 여전히 `until_start_seconds < 0`이었다. 이 실행의 공개 답변으로 별도 점검한 결과, 예약 생성 후 300초일 때 이용 시작 1초 전·정각·1초 후의 기대값은 각각 허용·거부·거부였고 실제 결과는 허용·허용·거부였다. 이 세 점검은 원 실험 종료 후 원인을 확인하는 데만 사용했다.

## 비교 방법

Qwen2.5-Coder-7B, Qwen2.5-Coder-14B, Qwen3-8B(추론 끔)의 [기존 첫 제출](../README.md)에서 출발했다. 각 모델의 시드 17·29·43에 대해 동일한 초안, 최초 질문과 운영자 답변을 두 검토 조건에 복제했다. 검토를 시작하는 시점은 첫 코드 제출 직후다. 모든 에이전트는 해당 메인과 같은 로컬 모델을 사용했다.

| 조건 | 초안 이후 작업 | 추가 호출 |
|---|---|---:|
| 독립 감시자 3명 | 세 감시자가 같은 대화와 초안을 개별 검토한다. 각 감시자는 다른 감시자의 의견을 볼 수 없다. 메인이 세 의견과 추가 답변을 받아 한 번 수정한다. | 4회 |
| 메인 자체 검토 3회 | 메인이 같은 세 관점을 같은 순서로 검토한다. 다음 검토에서 이전 검토 내용을 볼 수 있다. 메인이 세 의견과 추가 답변을 받아 한 번 수정한다. | 4회 |

프로젝트 화면의 세 관점인 **개입 판단의 태도**, **집중하는 근거**, **인간에게 필요한 기여**를 사용했다. 두 조건 모두 검토당 출력 상한 320토큰과 최종 제출 상한 1,500토큰을 적용했다. 상한과 호출 수가 같아도 실제 입력 길이와 출력 토큰 수는 달라질 수 있다. 24GB Mac에서 모델 하나씩 실행했고, 세 감시자 호출은 하나의 실행 슬롯을 순서대로 사용했다.

각 검토는 의견과 담당자에게 보낼 질문을 따로 제출했다. 한 초안의 질문을 한 번에 모아, 운영자 역할의 실험자가 [고정 답변 카드](../../../reservation_benchmark/evaluator/HUMAN_POLICY_BASIC.md)에서 해당 항목만 골라 답했다. 질문이 없으면 추가 정보를 제공하지 않았다. 모델은 원래 점수, 평가용 40문항, 정답, 다른 조건의 결과를 볼 수 없었다. 재채점 시 기존 시간 변환 함수와 채점 기준을 적용했다.

**새로 맞힘**은 초안의 오답이 최종 제출에서 정답이 된 문항 수이고, **새로 틀림**은 그 반대다. 변화량은 같은 문항을 시드별로 짝지어 계산했다. 각 모델의 분모 120은 같은 40문항을 세 초안에서 평가한 횟수다. 비교 대상은 이 과제에서의 한 차례 검토와 수정이며, 초기 계획부터 상시 감시하거나 여러 번 수정하는 웹 실행기 전체의 성능은 별도 실험 대상이다.

## 재현

기존 실험과 같은 로컬 모델을 포트 18751에서 시작한 뒤 저장소 루트에서 아래 명령을 실행한다. 기존 기록이 있으면 완료한 단계를 재사용한다.

```sh
python3 -B -m experiments.monitor_pilot review 7b-seconds
python3 -B -m experiments.monitor_pilot finish 7b-seconds --answers experiments/pilot-qwen/three-monitors/answers/7b-seconds.json
```

14B는 `14b-seconds`, Qwen3-8B는 `qwen3-8b-off`를 사용한다. 각 제출 기록에는 원본의 파일명과 SHA-256, 검토 요청과 응답 세 건, 운영자 답변, 메인의 수정 요청·응답, 토큰 사용량, 최종 코드, 문항별 판정이 들어 있다.

감시자가 직접 사례를 내는 조건과, 일반 감시의 마지막 수정 요청에 확정된 규칙의 실행 결과를 추가하는 조건은 다음 명령으로 재현한다. 마지막 명령에는 같은 시드의 일반 감시 기록이 필요하다.

```sh
python3 -B -m experiments.monitor_pilot review 7b-seconds --probes
python3 -B -m experiments.monitor_pilot finish 7b-seconds --probes --answers experiments/pilot-qwen/three-monitors/answers/7b-seconds-probes.json
python3 -B -m experiments.contract_replay 7b-seconds
```
