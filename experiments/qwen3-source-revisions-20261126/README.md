# 예약 취소 실험에서 수정안을 최종 코드까지 반영하기

공개 안내문만 받은 로컬 Qwen3-8B가 예약 취소를 허용할지 판정하는 실험이다. 한 번의 제출, 단일 에이전트의 자체 수정, 역할을 나눈 A·B·C·D를 같은 초안에서 비교했다. 모델이 제안한 수정이 코드에 들어갔는지와 그 수정이 정확도를 높였는지를 따로 측정했다.

!기존 독립 후보 선택과 수정 조건을 차례로 반영하는 새 파이프라인 (로컬 보관 자료)

## 5회 호출에서의 실제 결과

| 방식 | 기본 40문항 × 12시드 | 추가 56개 × 12시드 |
|---|---:|---:|
| 같은 단독 초안 | 343/480 | 512/672 |
| 전체 규칙표 재작성 · 단일 | 245/480 | 442/672 |
| 전체 규칙표 재작성 · A·B·C·D | 273/480 | 480/672 |
| 원본 보존 순차 수정 · 단일 | 338/480 | 476/672 |
| 원본 보존 순차 수정 · A·B·C·D | 344/480 | 441/672 |

원본 보존 방식은 전체 규칙표를 다시 쓴 A·B·C·D보다 기본은 71점 높고 추가 입력은 39점 낮았다. A·B·C·D의 B는 모든 시드에서 코드를 바꿨다. C는 한 시드에서 출력 코드를 바꿨고 D가 새로 출력 코드를 바꾼 시드는 없었다. B 이후 C와 D는 기본·추가 입력의 판정을 한 건도 바꾸지 못했다. 규칙 편집 요청이 들어오고 코드에 반영되는지와 채점 입력에서 실제 행동이 달라지는지를 구별해야 하는 이유다. 단계별 변경과 짝비교 (로컬 보관 자료) · 모델 요청·수정 이력 검증 (로컬 보관 자료)

실제 판정이 예약 후 경과 시간에 반응한 시드는 추가 입력에서 단독 0/12개, 원본 보존 A·B·C·D 10/12개였다. 시드 131에서 D는 단위를 올바르게 환산해 놓고도 일반 마감의 24시간을 예약 후 정정 기간에 사용했다. 이어서 두 시간의 기준을 구분하는 최종 검토를 두 비교군 모두에 한 번씩 적용했다. [6회 호출 최종 실험과 결과](../qwen3-public-clock-review-20261126/README.md)

## 이전 실험에서 놓친 요구

안내문에는 “방금 잘못 예약한 고객에게는 별도의 정정 시간이 있습니다.”라는 문장이 있다. 이용 시작까지 남은 시간이 같더라도 예약한 지 얼마나 지났는지에 따라 판정이 달라질 수 있다는 뜻이다. 정정 가능한 정확한 시간은 공개되지 않았다.

기존 6개 시드의 독립 후보 18개 중 1개는 응답이 잘려 함수를 읽을 수 없었다. 나머지 17개 중 예약 후 경과 시간(`age_seconds`)을 실행문에서 읽은 후보는 0개였다. 주석과 함수 설명을 걷어내면 12개는 초안과 코드 구조가 같았다. D가 선택한 6개 가운데 5개도 초안과 같은 구조였다. 결과적으로 40문항과 별도 56개 입력에서 모든 시드의 판정이 단독 초안과 같았다. [기존 고정 제출과 결과](../qwen3-blind-abcd-20261126/README.md)

순차 수정만으로 해결되는지도 확인했다. 첫 비교안은 B가 함수 전체를 규칙표로 다시 작성하고 C와 D가 항목별로 수정했다. 시드 131에서 B는 공개 문구 ‘24시간’을 `24`초로 옮겼다. 이 문제는 코드를 읽는 과정에서 발견했다. 새 방식에서는 기존 함수의 특정 반환 위치를 고르고, 공개 수치는 단위를 포함한 원문 값으로 참조하도록 했다. 전체 규칙표 방식의 시드 131 수정 이력 (로컬 보관 자료)

## 무엇이 달라졌나

| 단계 | 받는 자료 | 다음 단계에 남기는 결과 |
|---|---|---|
| A · 명세 해석 | 공개 안내문과 함수 계약 | 요구별로 바뀌어야 하는 판정, 관련 입력, 공개되지 않은 사항을 기록한다. A는 초안을 보지 않는다. |
| B · 구현 | 같은 메인 초안, A의 해석, 원문에 적힌 수량 | 적용할 위치와 비교 조건, 참·거짓 반환을 지정한다. 예를 들어 ‘24시간’에 대한 공개 참조는 86,400초로 변환된다. 미공개 기간을 가정하면 값과 단위를 함께 쓴다. |
| C · 검토 및 수정 | B의 현재 코드, 요구별 조건, 소스에서 읽은 분기 순서 | 요구별로 유지하거나 조건을 교체하고 이유를 남긴다. 지정한 수정은 프로그램이 즉시 코드에 반영한다. |
| D · 최종 통합 | C 반영 후의 전체 코드와 직전 변경 사유 | 같은 형식으로 누락이나 충돌을 직접 수정한다. 이 결과가 최종 제출이다. |
| 제출 후 평가 | 모든 시드와 비교군의 고정 제출 | 요청 원문과 함수 재구성 결과를 대조한 뒤 격리된 환경에서 40문항과 별도 56개 입력을 채점한다. |

수정할 위치는 함수 시작 또는 기존의 특정 반환문이다. 한 반환문 앞에 넣은 조건은 다른 반환 경로를 덮어쓰지 않는다. 변환기는 매번 삽입한 구문을 제거했을 때 원래 함수와 도우미 함수의 구문 구조가 그대로 복원되는지 확인한다. 유지, 설명만 변경, 동일 조건 재제출, 규칙 변경을 구분한다. 형식이 불완전한 응답은 사유와 함께 기록하고 직전 코드를 다음 단계로 넘긴다. [수정 위치와 단위 처리](../source_revisions.py) · [전달·검증 및 채점 순서](../serial_revisions.py)

코드에 조건이 생겨도 원래 반환과 항상 같으면 판정은 달라지지 않는다. C와 D에는 코드만 읽어서 증명되는 경우에 한해 이 점을 표시한다. 단순한 분기에서는 그 위치에 도달할 수 있는 범위와 양립하는지, 같은 위치의 앞선 조건이 새 분기를 덮는지도 확인한다. 이 과정에서 입력 예시를 실행하거나 기대 판정을 대조하지 않는다.

## 비교 조건

- **단독과 자체 수정**. 단독은 메인 초안 1회다. 자체 수정은 같은 개발자 역할이 초안에 이어 최초 변경, 검토 2회, 최종 반영을 수행한다. A·B·C·D와 총 5회로 맞췄고 수정 형식과 변환기도 공통으로 제공했다. 상한은 초안 1,500토큰, 후속 호출 각각 1,152토큰이다. 호출 수와 상한을 맞춰도 실제 사용 토큰은 다를 수 있다.
- **기존 시드와 새 시드**. 기존 131·157·191·223·257·293에 새로 지정한 307·331·353·379·401·419를 추가했다. 새 시드는 모델 생성의 변화를 확인하기 위한 것이다. 채점에 사용한 40문항과 별도 56개 입력은 전 시드에서 동일하다.
- **가채점 차단**. 모델은 공개 문장, 소스와 이전 단계가 적은 사유만 받는다. 후보를 실행한 출력, 정답 예시, 점수로 고른 후보나 재호출은 없다. 12개 시드의 초안·자체 수정 중간본·자체 수정 최종본·B·C·D를 모두 고정한다. 이후 로컬 모델 서버를 종료하고 각 호출에 보낸 메시지와 최종 코드를 원문에서 재구성한 뒤 채점한다.
- **두 순차 방식 사이의 짝맞춤**. 전체 규칙표와 원본 보존 방식은 12개의 초안과 12개의 A 해석 원문을 공유한다. 복사할 수 있는 자료는 두 종류의 호출 기록으로 한정했다. 각 방식의 B·C·D와 단일 에이전트 수정은 따로 생성했다. 고정한 실험 설계 (로컬 보관 자료)

## 재현

프로젝트 루트에서 원본 보존 방식 하나만 실행할 수 있다.

```sh
python3 -B -m experiments.monitor_cycles --serial-revisions experiments/새결과폴더
```

두 순차 방식을 초안과 A 응답까지 동일하게 맞추려면 아래 두 명령을 순서대로 실행한다.

```sh
python3 -B -m experiments.monitor_cycles --rule-table-revisions experiments/새규칙표폴더
python3 -B -m experiments.monitor_cycles --serial-revisions --shared-inputs-from experiments/새규칙표폴더 experiments/새원본보존폴더
```
