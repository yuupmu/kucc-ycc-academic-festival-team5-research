# Qwen3 검토 편집자 D의 요약과 코드 추적 비교

두 조건 모두 64/80점(80.0%)이었다. 같은 시드의 두 수정본은 파이썬 구문 트리와 40개 판정이 모두 같았다. 코드 추적을 지시한 D가 기존 분기 순서 때문에 정정 예외가 아무 결정도 바꾸지 못한다는 점을 정확히 진단한 사례는 0/2건이었다. 기존 요약 D도 0/2건이었다.

| 고정한 시점 | 수정 전 | 요약 D 후 | 추적 D 후 | 요약 D+메인 토큰 / 시간 | 추적 D+메인 토큰 / 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 시드 29, 2회차 | 30/40 | 34/40 | 34/40 | 2,848 / 10.33초 | 3,884 / 20.85초 |
| 시드 43, 3회차 | 30/40 | 30/40 | 30/40 | 2,905 / 12.19초 | 3,066 / 13.75초 |
| 합계 | 60/80 | 64/80 | 64/80 | 5,753 / 22.52초 | 6,950 / 34.60초 |

두 조건 모두 모델을 4회씩 호출했다. 요약 조건은 입력 4,821토큰과 출력 932토큰, 추적 조건은 입력 5,474토큰과 출력 1,476토큰을 사용했다. 추적 지시는 두 사례 합계로 1,197토큰과 12.08초를 더 썼다. 시간은 D와 메인의 응답 대기 시간 합이며 모델 로딩·채점은 제외했다.

### 무엇이 달라졌나

- **시드 29.** 요약 D는 시간 기준이 불확실하다고 전달했다. 추적 D는 A의 예시인 ‘예약 후 100초, 시작까지 3,000초’를 인용했으나 현재 코드가 맨 앞의 24시간 조건에서 거부한다는 것을 밝히지 못했다. 두 메인 모두 정정 조건에 도달할 수 있도록 앞부분을 바꿨다. 그러나 예약 후 경과 시간은 사용하지 않았고, 시작까지 0초 이상 1시간 미만이면 취소를 허용했다. 덕분에 시작 1초 전 5건이 정답으로 바뀌고, 시작 정각 1건이 새 오답이 됐다. 정확히 예약 후 10분이면서 시작까지 1~5시간 남은 5건은 계속 거부했다. ### 해석

시드 29의 4점 향상은 두 조건에 공통이다. 원문 피드백을 모두 실은 요약 조건에서도 관찰됐다. 실제로 두 시드 모두 요약 D의 응답 본문이 직전 실험과 문자 단위로 동일했다. 메인에 전달한 개별 피드백 원문이 이전 실험과 달라졌으며, 이번 두 조건 간의 차이는 D의 지시문뿐이다.

두 추적 D 모두 핵심 결함을 진단하지 못했다. 따라서 이 자료로는 정확한 진단이 도달했을 때 메인이 얼마나 반영하는지 추정할 수 없다. 또한 같은 40문항을 두 시점에서 적용했으므로 합계 80개는 독립된 문제 80개를 뜻하지 않는다.

## 비교 설계

앞선 실험에서 일반 취소 마감 뒤에 정정 예외가 작동하지 않았던 시드 29의 2회차와 시드 43의 3회차를 골랐다. 각 시점에서 메인이 수정을 시작하기 직전 코드 하나와 A·B·C의 질문·피드백 세 쌍을 고정했다. 각 조건에서 D와 메인이 한 번씩 새로 응답한다. 동일 과제의 알려진 실패 두 건을 비교하므로 새로운 과제나 시드에 대한 성능 추정에는 사용할 수 없다.

| 항목 | 두 조건에 적용한 방법 |
| --- | --- |
| 조작변인 | 요약 조건은 기존 D 지시문을 사용한다. 추적 조건에서는 감시 의견의 입력 사례로 함수의 첫 반환까지 따라가고, 조건의 효과와 불확실성을 근거와 함께 같은 출력 양식에 적도록 한다. |
| 감시자 원문 | 두 D의 사용자 메시지는 저장된 원래 D 호출과 동일하다. 두 메인 모두 D의 정리문과 감시자 셋의 질문·피드백 원문 전체를 받는다. 이전 실험에서 비었던 개별 피드백 칸도 두 조건에 똑같이 채운다. |
| 모델과 생성 설정 | Qwen3-8B Q4_K_M, 추론 끔, 온도 0.3, top-p 0.9, top-k 40. 같은 쌍에서는 같은 시드를 쓰고 D와 메인의 출력 상한은 각각 800·1,500토큰으로 고정한다. |
| 메인과 정보 | 공개 과제, 입력 코드, 메인의 시스템·수정 지시와 전달 양식을 고정한다. 메인과 D의 직접 질문, 추가 감시자 호출, 담당자 답변은 없다. 모델에게 중간 실행, 비공개 정답, 점수를 제공하지 않는다. |
| 비용과 순서 | 시드 29는 요약을, 43은 추적을 먼저 실행한다. 비용은 새로 호출한 D와 메인의 입력·출력 토큰 및 응답 대기 시간만 합산한다. |

### 판독 기준

1. **D의 진단.** 전체 함수의 반환 순서나 조건의 포함 관계를 근거로 정정 조건이 기존 허용·거부를 바꾸지 못함을 명시했는지 확인한다. 정책 시간에 의문만 제기하거나 한 분기의 결과만 적으면 완전한 진단으로 세지 않는다. 전달문의 예시가 코드와 일치하는지도 별도로 확인한다.
2. **메인의 반영.** 제출한 코드에서 일반 마감 후, 이용 시작 전인 고객의 취소 여부가 예약 경과 시간에 따라 실제로 달라지는지 본다. 조건을 추가해도 같은 곳에서 반환되면 구현 결함이 남아 있다. 공개되지 않은 유예 시간의 수치를 추측했는지는 따로 기록한다.
3. **최종 점수.** 네 수정본이 모두 저장된 후 동일한 비공개 40문항으로 일괄 채점한다. 수정 전에서 정답으로 바뀐 문항과 새 오답을 모두 보존한다.
