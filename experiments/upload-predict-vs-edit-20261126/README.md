# 16바이트에서 받은 답을 값과 코드에 각각 반영한 결과

2026년 11월 26일 · 업로드 단일 과제 · Qwen3.5-4B Q4_K_M

**값 예측은 18/18, 제출 코드의 실행값은 13/18이었다.** 차이가 난 5건은 모두 ‘정확히 16바이트면 거부’라는 답을 받은 조건에서 나왔다. 세 시드 모두 15바이트는 허용해야 한다고 답했지만, 그 조건에서 15바이트를 실제로 허용한 코드는 하나도 없었다.

## 같은 자료를 받은 두 역할

기존 실험에서 사용한 공개 명세·시작 코드·감시자 질문·첫 담당자 회신을 가져왔다. 모델에 보낸 첫 사용자 메시지는 같은 정책·시드의 두 역할에서 바이트 단위로 같았다. 정책 A와 B의 회신에서는 한 문장만 다르다. 양쪽 모두 상한은 16바이트이며 0바이트 빈 파일은 거부한다고 답했다. 공개 명세에는 상한보다 작은 양수는 허용하고 큰 양수는 거부한다고 쓰여 있다. 기존 명세와 회신 (로컬 보관 자료)

| 정책 | 담당자가 바꾼 문장 | 15바이트 기대값 | 16바이트 기대값 | 17바이트 기대값 |
| --- | --- | --- | --- | --- |
| A · 상한 포함 | 정확히 상한이면 허용합니다. | 허용 | 허용 | 거부 |
| B · 상한 제외 | 정확히 상한이면 거부합니다. | 허용 | 거부 | 거부 |

작성 역할은 기존 편집기와 같은 요청으로 코드를 새로 수정했다. 세 검사 입력이나 예측 결과는 전달하지 않았다. 코드 여섯 개를 고정하고 모델 서버를 종료한 뒤 같은 가중치로 별도 서버를 열었다. 예측 역할에는 15·16·17바이트를 명시하고 각 입력의 정책상 결과를 ‘허용·거부·판단 보류’ 중 하나로만 답하게 했다. 두 역할 모두 시드 273·419·887, 온도 0.3, 동일한 첫 출력 한도를 사용했다. 사전에 정한 정답과 채점 절차는 모든 제출을 고정한 뒤에 적용했다. 실험 설계 (로컬 보관 자료) · 제출 해시 (로컬 보관 자료)

## 예측과 실행값

아래 세 값은 항상 **15 / 16 / 17바이트** 순서다. `None`은 함수가 불리언을 반환하지 않고 끝났다는 뜻이다.

| 시드 | 정책 | 모델이 직접 고른 값 | 제출 코드를 실행한 값 | 코드 정답 |

| 273 | A · 포함 | 허용 / 허용 / 거부 | 허용 / 허용 / 거부 | 3/3 |
| 273 | B · 제외 | 허용 / 거부 / 거부 | `None` / `None` / 거부 | 1/3 |

두 역할이 함께 맞힌 입력은 13건, 값 예측만 맞힌 입력은 5건이었다. 코드만 맞히거나 양쪽 모두 틀린 경우는 없었다. 예측에서는 세 시드 모두 A와 B의 판단이 16에서만 바뀌었다. 코드에서는 16에서 두 정책을 각각 맞힌 시드가 2/3이었고, 15·17까지 함께 맞힌 정책 쌍은 0/3이었다. 입력별 실행값과 실행 줄 (로컬 보관 자료)

## 제외 정책의 오류는 어느 단계에서 생겼나

| 시드 | 모델이 양수 처리 위치에 제안한 수정 | 실제 영향 |
| --- | --- | --- |
| 273 | `size_bytes > 16`일 때 거부하고, 그 반환문 뒤에 `size_bytes == 16` 검사를 들여썼다. | 15와 16에서는 반환문에 도달하지 못해 `None`이 됐다. |
| 419 | 양수 분기를 `return False`로 교체했다. | 16을 거부하는 동시에 허용해야 할 15도 거부했다. |
| 887 | 양수 분기에 `return size_bytes > 16`을 썼다. | 16은 거부했으나 15를 거부하고 17을 허용했다. |

여섯 수정안이 모두 첫 시도에 적용됐다. 모델 응답 원문의 수정을 시작 코드에 다시 적용하자 실제 제출 파일 여섯 개를 그대로 재현했다. 여섯 파일은 이전 짝실험의 같은 조건에서 보관한 파일과도 바이트 단위로 같았다. 제외 조건의 오류 세 가지는 이미 모델이 낸 수정안에 들어 있었다. 273 수정안 (로컬 보관 자료) · 419 수정안 (로컬 보관 자료) · 887 수정안 (로컬 보관 자료)

## 해석과 비용

이 사례의 작성기는 구체적인 입력을 주면 양쪽 정책에 맞는 값을 모두 지정했다. 반면 일반적으로 사용할 조건문을 쓰게 하면, 제외 정책에서 기존의 ‘상한보다 작은 양수는 허용’ 규칙을 세 번 모두 보존하지 못했다. 이 결과는 서로 다른 지시에서 관찰한 두 출력의 차이를 보여 준다. 코드를 쓰던 순간의 내부 판단을 직접 관찰한 것은 아니다.

측정 단위는 과제 한 개의 세 입력을 정책 두 가지와 시드 세 개에서 반복한 18건이다. 예측 쪽에만 검사 입력이 명시됐다. 값 예측을 코드 작성기에 전달했을 때 개선되는지, 다른 과제나 모델에서도 같은 경향이 나오는지는 이 실험에서 평가하지 않았다.
