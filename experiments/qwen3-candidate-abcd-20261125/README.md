## 조정의 근거

기존 파이프라인은 A·B·C가 문제를 지적하고 D가 의견을 요약한 뒤, 메인이 코드를 다시 작성했다. 질문이 있으면 같은 감시자의 피드백 원문이 전달 묶음에서 빠지는 경우가 있었고, D는 두 실패 코드에서 허용·거부를 9/18번 맞혔다. 같은 검토를 두 번 더 반복해도 채점 결과는 바뀌지 않았다. [기존 검토 주기](../qwen3-review-cycles-20261125/README.md) · [D의 판독 실험](../qwen3-editor-opinions-20261125/README.md)

첫 조정에서는 A·B·C·D와 메인에게 실제 실행값을 전달하고, 기존에 통과한 검사를 보존하는 수정만 채택했다. 완전정보에서 단독 215/240점이 225/240점으로 올랐으나, 공개 안내문만 준 조건은 모두 175/240점이었다. 시드 43·71·89의 수정안이 정정 시간을 ‘예약 후 정확히 0초’로 구현해 공개 예시는 통과하고 원래 벤치마크의 정정 사례를 계속 틀렸다. 메인에게 반례를 한 번 더 전달해도 점수는 그대로였다. ## 채택하는 코드를 바꾼 방법

1. 메인이 기존 실험과 같은 명세로 초안을 만든다. 공개 안내문 조건에는 문서에서 특정할 수 없는 유예 기간과 경계값을 주지 않는다. 완전정보 조건은 이전 단일 모델 실험의 운영 명세 전문을 사용한다.
2. 모든 수정 조건에서 같은 공개 검사를 실행한다. 예약 생성 순간과 오래된 예약에 더해 **예약한 지 1초이고 이용까지 각각 4시간·12시간 남은 경우**를 두었다. ‘별도의 정정 시간’이 양의 기간이라는 안내문 해석을 명시적으로 검사한다. 몇 분까지 허용되는지는 부분정보에서 계속 미확정이다. 초안이 해당 조건의 공개 검사를 모두 통과하면 바로 제출한다.
3. 실패가 있으면 A는 명세의 적용 순서, B는 입력 변수와 허용 조건의 조합, C는 규칙이 겹칠 때의 우선순위에 집중해 각각 실행 가능한 함수 전체를 제안한다. 초안, 안내문, 초안의 실제 실행 표를 공통으로 받고, 미명시 기간을 가정할 때는 코드에 표시한다. 세 제안 모두 같은 Qwen3-8B에서 생성한다.
4. 초안의 통과 사례를 모두 유지하면서 한 건 이상 추가로 통과한 후보만 남긴다. 그중 통과 수가 가장 많은 후보가 하나면 그대로 선택한다. 공동 1위가 여럿이면 D가 원문 코드와 실제 실행 표를 보고 하나를 고른다. 실험기가 선택 범위를 제한한다. 선택된 코드는 그대로 보존해 D의 판단을 메인이 다시 코드로 옮기는 단계를 없앴다.
5. 선택 뒤에도 공개 검사 실패가 남은 경우에 한해, 초안과 감시 의견을 가린 새 대화에서 명세와 공개 예시만으로 대체 함수 하나를 만든다. 선택된 함수의 통과 사례를 모두 보존하며 더 많이 통과할 때만 교체한다. 기존 시드 43·89의 완전정보 조건에서 세 후보가 초안과 똑같은 공개 검사를 틀린 것을 보고, 새 시드 최종 채점 전에 이 예외 경로를 정했다. 짧은 자체 검토와 순차 자체 검토에도 같은 기회를 주며 같은 시드·정보 조건에서는 복구 응답 하나를 공유한다. 복구 단계의 설계 (로컬 보관 자료)

| 비교 조건 | 같은 초안 이후의 처리 |
|---|---|
| 단독 제출 | 초안을 바로 제출 |
| 단일 에이전트 1회 수정 | 공통 후보 A를 검증해 초안과 비교 |
| 단일 에이전트 순차 수정 | 같은 개발자가 A를 보고 B를, A·B를 보고 C를 제안. 동률이면 자체 선택 |
| A·B·C·D | A·B·C는 서로의 코드를 보지 않고 독립 제안. 동률이면 D가 선택 |

한 정보 조건·시드에서 네 방식은 같은 초안을 공유한다. 수정 세 방식은 첫 후보 A의 응답까지 공유한다. 순차 수정과 독립 제안은 같은 관점·검사·후보 수·출력 상한을 사용한다. 세 후보와 복구 호출은 각각 최대 800토큰, 동률 판정은 최대 80토큰이다. 초기 검사 통과 시 한 번의 초안 호출로 종료하며, 최대 호출 수는 복구까지 포함해 6회다. 독립 제안도 로컬 서버에서 차례로 생성한다. 시간은 각 조건의 공통 호출을 한 번씩 포함한 모델 응답 대기 시간의 합이다.

## 평가 범위

Qwen3-8B Q4_K_M, 추론 끔, 온도 0.3, top-p 0.9, top-k 40을 고정했다. 설계에 사용한 시드는 17·29·43·71·89·113이다. 수정안의 재현성을 확인할 시드 131·157·191·223·257·293을 실행 전에 고정하고 모든 제출을 끝낸 뒤 일괄 채점했다. 비공개 점수와 정답은 후보 생성 및 선택에 사용하지 않았다. 같은 정책의 기존 40문항과 별도 56개 입력을 따로 집계한다. 56개 입력은 양쪽 정보 조건의 모든 공개 검사 및 기존 40문항과 겹치지 않는다. 실험 설계 (로컬 보관 자료) · [후보 생성·선택 코드](../candidate_cycles.py) · [별도 입력의 구성](../cancellation_transfer.py)

두 세대의 차이에는 공개 검사의 보완, 감시자의 역할과 프롬프트, 후보 선택, 마지막 재작성 생략이 함께 포함된다. 각 변경의 개별 효과는 분리하지 않았다. 추가 시드는 새 모델 생성에 대한 확인이며 다른 서비스 정책이나 과제의 성능을 검증한 것은 아니다.

## 재실행

프로젝트 루트에서 `python3 -B -m experiments.monitor_cycles --candidates experiments/새비교폴더`를 실행한다. 기존과 같은 로컬 모델 파일과 macOS 격리 실행기를 사용한다. 시드별 폴더의 `draft.json`과 `A.json`에는 공통 응답, 각 조건의 `decision.json`에는 선택 가능 후보·실제 선택·공개 검사 전부, `score.json`과 `transfer.json`에는 최종 채점 내역이 들어 있다. 초안이 공개 검사를 전부 통과하면 A 호출은 생략된다.
