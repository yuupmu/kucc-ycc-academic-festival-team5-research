업로드 경계에서 기존 오답 5건을 모두 고쳤고 기존 정답 1건을 잃었다. 15·16·17바이트를 정책 2개와 시드 3개에 적용한 결과는 **13/18 → 17/18**이었다. 정확히 16바이트를 포함하는 답과 제외하는 답에 모두 맞고 나머지 35개 정수에서도 두 제출이 모두 맞은 시드는 **0/3 → 2/3**이었다. 최종 집계 (로컬 보관 자료) · 동결한 제출 (로컬 보관 자료)

## 실제 변경

기존에는 메인이 담당자의 회신을 읽고 교체할 원문과 새 실행문을 한 번에 썼다. 채택한 실험 버전에서는 메인이 먼저 공개 명세와 회신을 읽고 입력 조건별 동작을 정리한다. 정수 인수 하나를 받는 참·거짓 함수에 미구현 지점이 있고, 회신 근거가 한 구절로 연결되며 별도의 코드 수정 지적이 없으면, 같은 메인이 참인 범위와 거짓인 범위를 각각 비교식으로 쓴다. 편집기는 두 식이 모든 정수를 빈틈이나 겹침 없이 나누는지 확인하고 기존 미구현 위치에만 반환문을 넣는다. 나머지 경로에는 기존 직접 편집기를 쓴다. [실행 코드](../reply_pipeline.py) · [범위 확인과 국소 편집](../guarded_reply.py)

비교식에는 정수, 인수 이름, 비교, 논리 결합을 허용한다. 비교식에서 단일 등호도 동등 비교로 읽는다. 범위가 불완전하거나 겹치면 해당 편집을 보류한다. 이 검사는 모델이 제안한 두 식의 구조만 사용한다. 모델 입력에는 공개 명세·초안·해당 조건의 문답과 내부 작성 메모가 들어가며, 평가 입력·기대값·실행 결과·점수는 전달하지 않는다.

업로드는 시드 273·419·887과 상한 포함·제외를 조합한 제출 6개다. 216건은 서로 다른 36개 정수를 여섯 제출에 반복한 개수다. 센서는 시드 419에서 같은 ID의 첫 값·마지막 값을 보존하는 두 정책에 입력 순서 341개씩을 평가했다. 계측 과제는 시드 1421에서 기준값 −3보다 큰 신호를 재검하고, 정확히 −3의 취급만 뒤집었다. 각 정책에 −12~6의 정수 19개를 썼다. 작성 토큰은 입력과 출력을 합친 값이다. 초안·감시자·담당자 문답 비용은 이 비교에서 제외했다. 메모 실험 (로컬 보관 자료) · 동작 선택 실험 (로컬 보관 자료) · 범위 실험 (로컬 보관 자료) · 값 예측 실험 (로컬 보관 자료) · 계측 비교 (로컬 보관 자료)

첫 방식에서는 상한 변수에 16을 대입하고 함수가 반환할 값을 빠뜨렸다. 두 번째 방식에서는 초안의 빈자리를 정확히 지정해도 업로드 여섯 제출 모두 보류를 선택했다. 센서에는 첫 값·마지막 값 양쪽에 같은 `continue`를 넣었다. 전체 범위를 쓰는 방식은 이 문제를 줄였고, 제외 정책 시드 419의 거짓 범위에는 `size_bytes = 16`처럼 수학식 등호가 들어갔다. 이 표기를 허용한 뒤 같은 원본 응답을 다시 적용하자 해당 제출이 회복됐다. 마지막 비교에서는 모델을 다시 호출하지 않고 열 제출의 실제 요청과 원본 출력을 재생했다. 표에는 이 방식으로 새로 실행할 때 쓰는 전체 호출 토큰을 계상했다. 419 제외 정책의 실제 제출 (로컬 보관 자료) · [재생과 검증 절차](final_replay.py)

넓은 업로드 검사에서 기존 정답 153건 중 152건을 유지했고 기존 오답 63건을 모두 고쳤다. 남은 오답은 시드 887의 포함 정책이다. 담당자는 정확히 16도 허용한다고 답했고, 메인은 `0 < 크기 < 16`에 해당하는 참 범위와 16 이상을 포함한 거짓 범위를 제출했다. 두 식은 정수 전체를 빠짐없이 나누므로 구조 검사를 통과했다. 반대 정책에서 16이 거부되어야 한다는 조건은 올바르게 구현했다. 887 포함 정책 제출 (로컬 보관 자료) · 반대 답의 제출 (로컬 보관 자료)

센서 두 제출은 기존 코드와 바이트 단위로 같았다. 기존 오답 64건도 남았다. 작성 토큰은 1,610에서 2,499로 늘었다. 계측에서는 두 방식 모두 38/38이고 토큰은 644에서 1,560으로 늘었다. 이 수치는 알려진 업로드 실패를 보며 수정한 개발 비교의 결과다. 계측 과제도 최종 방식 선택 전에 한 번 확인했다. 감시자들의 질문 생성 성능이나 전체 세 회차의 성능을 다시 측정한 실험은 아니며, 벤치마크에는 고정한 질문과 답을 사용했다.

## 실행

프로젝트 루트에서 새 폴더로 시작한다. 실행기는 공개 초안을 공유하고, 자체 검토와 감시자 A·B·C 조건에서 각각 세 회차를 진행한다. 질문이 생기면 해당 조건은 자연어 답변을 받는 시점까지 기다린다. 전체 실행을 시험할 때 입구는 다음과 같다.

```sh
python3 -B -m experiments.reply_pipeline upload var/새실험
python3 -B -m experiments.reply_pipeline upload var/새실험 --reply-to abc-1 --answer-file 담당자회신.txt
```

질문과 답은 조건·회차별 파일에, 편집 시도와 코드는 회차별 스냅숏에 남는다. 공개 프로젝트 JSON의 `brief`와 `files.solution.py`를 사용해 다른 함수에도 실행할 수 있다. 최종 실험 설계 (로컬 보관 자료)
