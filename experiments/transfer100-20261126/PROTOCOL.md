# 새 유형 100문항의 비교 설계

이번 비교의 단위는 서로 다른 공개 개발 과제 5개와 과제마다 서로 다른 입력 20개다. 각 조건은 과제별로 함수 하나를 작성한다. 총 100문항은 그 다섯 프로그램의 동작을 평가한다. 모든 역할은 Qwen3.5-4B Q4_K_M, 시드 263, 같은 생성 설정을 사용한다.

| 과제 | 공개한 동작 | 질문해서 확인할 정책 | 주요 관찰 |
|---|---|---|---|
| 제목 정리 | 양끝 공백 제거, 소문자, 숫자 유지 | 연속 공백, 하이픈, 빈 제목 | 변환 대상과 결합, 기본값 |
| 확장자 추출 | 이름 가운데 점 하나 뒤 문자열 | 대소문자, 여러 점, 숨김 이름, 없는 확장자 | 마지막 구분자, 예외, 빈 출력 |
| 식별코드 가림 | 글자별 별표, 길이·표기 보존 | 공개 위치·개수, 짧은 코드 | 범위와 예외의 우선순위 |
| 업로드 크기 | 음수 거부, 상한 양쪽의 동작 | 상한, 같은 크기, 빈 파일 | 숫자와 경계 포함, 0 |
| 인쇄 영역 | 두 길이 비교, 음수 거부, 고정 방향 | 각 상한, 같은 길이, 0인 길이 | 변수 대응, 두 조건 결합 |

과제는 상태를 저장하지 않는 함수 하나로 풀 수 있다. 문자열은 명시된 ASCII 범위, 수치는 정수 바이트 또는 센티미터를 사용한다. 입력 형식, 반환 형식과 기본 동작을 공개해, 앞선 예약 과제의 여러 시각·기간을 조합하는 부담을 줄였다. 실제 난이도와 점수는 실행 후 측정한다.

비교하는 구조는 인간 개입이라는 목표가 확정된 이후의 21조건이다.

- ① 메인 단독 1조건
- ② 메인 자체 검토와 담당자 회신을 받는 기존 작성, 일반 코드, 자유 조건식, 입력 영역, 이전 3회차, 현재 3회차 6조건
- ③ 공통 관점 P1, 역할 분담 P2, 상황·두 결과 P3, 질문 정리 P4, 적용 근거 확인 P4 보완 5조건
- ③ 질문 개선만 적용한 기존 작성 1조건
- ③ P4 질문·동일 회신과 일반 코드·자유 조건식·입력 영역을 결합한 3조건
- ③ 능동 질문·동일 회신과 일반 코드·자유 조건식·입력 영역을 결합한 3조건
- ③ 이전 3회차와 현재 3회차 2조건

이전의 중간 채점 노출 조건과 예약 전용 A/B/C/D 후보 선택 실험은 비교 목록에서 제외했다. 현재 규정과 과제 범위를 만족하는 재사용 가능한 파이프라인들의 변화를 비교한다.

최초 코드와 같은 질문 방식의 첫 질문·회신은 공유한다. 3회차 조건은 회차마다 자기 직전 코드를 읽어 새 질문을 만든다. 현재 구조와 이전 구조의 두 번째 이후 질문은 실제 코드가 달라지면 달라질 수 있다. 이 차이는 전체 운영 효과에 포함한다. 한 회차에서 최대 세 질문을 한 묶음으로 전달하고 대리 담당자가 자연어로 답한다.

담당자는 질문별로 사전 정책의 해당 문장만 고른다. 질문이 기존 가정을 확인하려 해도 고정 정책이 다르면 실제 정책을 답한다. 구체적인 정책 영역을 여러 개 명시해 요청하면 그 범위의 규칙을 함께 답한다. 질문 범위를 정할 수 없으면 구체화를 요청한다. 공개 명세의 범위를 벗어난 입력을 묻는 경우 공개 범위를 재안내한다. 선택한 정책 번호와 근거는 연구자 기록에 남기고 모델에는 질문과 자연어 회신만 제공한다.

모든 조건의 최종 코드 105개를 고정한 뒤 평가한다. 회차 중에는 모델이 공개 명세·받은 답변·코드만 읽는다. 숨겨진 문항, 기대값과 실행 결과는 최종 평가 과정에만 들어간다. 최종 평가에서 첫 코드와 회차별 사본도 실행해 어느 입력이 개선되거나 퇴행했는지 기록한다.

측정값은 정답, 잘못된 반환, 판단 보류, 정책 확보 전 반환, 답을 받은 뒤에도 남은 실패, 실제 모델 호출·입력 토큰·출력 토큰·소요 시간이다. 정보 충족 여부는 문항별 사전 정책 목록과 실제 받은 회신으로 판정한다. 공개 요구만으로 결과가 정해지는 문항은 별도로 추적한다. 두 인쇄 치수가 모두 상한을 넘는 경우 어느 한쪽의 상한을 알아도 거부 결과를 정할 수 있으므로 그 대체 근거를 인정한다.

동일 요청의 원응답을 재사용한 경우 각 조건의 비용에는 해당 호출의 실제 사용량을 포함한다. 전체 실험의 실소모는 고유 호출을 한 번씩 세어 별도로 기록한다. 응답 없이 끊긴 전송은 토큰 사용량을 알 수 없어 계측 누락으로 표시한다. 질문·수정 기회와 총 토큰 예산이 다른 구조들 사이에서는 비용과 점수를 함께 읽는다.
