# 600초에서 거부가 나온 이유를 확인한 재실험

확인한 입력 조건은 예약 생성 후 정확히 600초이고 이용 시작이 0초 초과 24시간 미만 남은 경우다. 100문항 연구에서 R28~R32 다섯 입력이 모두 이 분기를 지난다. 1회차 코드의 반환은 허용, 2·3회차 코드의 반환은 거부였다. [당시 최종 코드](../../runs/reservation/live-multi/submissions/candidate/solution.py#L36)

## 같은 정책을 주고 판단 순서만 바꾼 결과

같은 로컬 Qwen3.5-4B, 같은 작성 시드 1263, 같은 시스템 지시, 같은 공개 명세 3문장과 대리 담당자 회신 7문장을 사용했다. 원래 요청에서 입력 영역 목록과 그에 대응하는 출력 항목만 조절했다. 100문항 실험 제출 후 작성기만 세 번 다시 호출했다. 실제 채점 문항, 정답, 점수, 검토자의 정오 평가는 입력에 넣지 않았다.

| 작성 요청 | 해당 조건의 출력 위치 | 반환 | 모델이 인용한 근거 |
|---|---:|---|---|
| [원래의 25개](original-order.json) | 18번째 | 거부 | P2, P3, H1, H2, H3 |
| [해당 조건 한 개](only-this-row.json) | 1번째 | 허용 | P2, P3, H1, H2, H3 |
| [같은 25개에서 해당 조건을 앞으로 이동](this-row-first.json) | 1번째 | 허용 | P2, H7 |

원래 순서에서는 보존한 2회차 모델 요청과 응답 본문 전체가 재현됐다. 이 모델과 시드에서는 같은 25개 조건 중 해당 조건을 맨 앞으로 옮기는 것만으로 결과가 바뀌었다. 한 개만 물을 때는 인용 원문 번호까지 그대로인 채 결과가 뒤집혔다. 앞으로 옮긴 조건의 답은 허용이지만, H7은 정정 기간이 끝난 뒤에도 일반 취소가 가능한 경우에 대한 설명이어서 이 입력의 허용을 뒷받침하지 않는다.

## 답변을 알고도 정반대 값이 통과한 경로

1. 담당자는 정정 기간이 10분이고(H2), 끝점도 기간에 속하며(H3), 일반 마감이 지났어도 정정 기간 안이면 정정할 수 있다(H5)고 답했다. 계획 단계의 메인은 H3를 “Correction period end instant is inclusive”라고 적었다. [당시 계획 원문](../../runs/reservation/live-multi/cycle-2/calls/33c9e5b599558effcf0a0ca6c83e7cf4d49a6eb29ee90206d31ab3b19bd051e0.json)
2. 반환을 고르는 호출에는 원문과 25개 영역, 허용·거부·보류 선택지가 들어간다. 직전 코드의 반환, 계획에서 풀어 쓴 규칙, 감시자의 수정 지적은 이 요청에 포함되지 않았다. 2회차 메인은 25개 모두에 같은 다섯 근거를 붙였다. 허용을 준 두 곳은 예약 경과 시간이 모두 0초 초과 600초 미만이었다. 해당 회신 H5는 어느 칸에서도 인용하지 않았다. [원래 작성 요청과 출력](../../runs/reservation/live-multi/cycle-2/calls/9df50b68fc80e0677ecdcaaffd09c5a715f6650752f32ed7aaf80bc6dc348124.json)
3. 회신을 코드에 직접 연결하는 검사는 각 문장을 개별로 읽는다. 이번에 H3의 “포함합니다”는 기간 경곗값 설명이라 허용·거부의 결정 문장으로 연결되지 않았다. 1회차의 대상 행에도 보존할 회신 근거가 등록되지 않았다. 같은 근거를 둔 채 해당 행의 반환만 허용과 거부로 바꿔 두 번 검사했더니 양쪽 모두 그대로 코드로 바꿀 수 있었고, 해당 행과 회신 검사에서 보고한 오류는 양쪽 모두 0개였다. [회신 연결 코드](../../../../backend/answer_contracts.py#L239) · [코드 생성 전 검사](../../../../backend/decision_regions.py#L115)
4. 2회차 제출 전 감시자 A와 C는 정확히 600초에서 코드 수정이 필요하다고 표시했다. 이 표시는 완료 여부를 평가할 때 쓰인다. 다음 작성 요청에 이 수정 지적을 넘기는 경로는 없다. 3회차에 담당자가 반복해서 준 문장들은 기존 원문과 중복되어, 작성기에 보낸 요청 및 재사용한 응답이 2회차와 일치했다. [2회차 검토 기록](../../runs/reservation/live-multi/cycle-2/snapshot.json) · [후속 질문과 수정 경로](../../collect.py#L102)
