# 운영 규칙을 모두 제공한 단일 모델 벤치마크

Qwen3-8B Q4_K_M 한 모델이 각 과제의 운영 정책과 입출력 계약을 첫 요청에서 받았다. 시드 17·29·43마다 독립적인 새 대화에서 한 번 생성한 함수를 채점했다. 감시자·담당자 질의·재수정은 0회였다.

## 첫 제출 점수

예약 취소에서는 일반 마감의 정각 포함, 생성 후 10분 유예의 경계, 이용 시작 이후 거부의 우선순위를 모두 제공했다. 이전 A는 같은 모델·시드·채점기로 먼저 질문한 뒤 답변을 받고 구현했다. 현재 실험은 완전정보를 한 번에 읽으므로 이전 A와 비교할 때 정보량과 대화 구조가 함께 달라진다.

자원 배정은 기존 프로젝트의 별도 벤치마크다. 입력 사건을 순서대로 처리하는 함수에 대해 좌석·장비 배정, 대기열 승격, 중복과 재전송, 취소·변경, 오류 우선순위와 알림을 명시했다. 입출력 계약, 출력 스키마, 운영 정책 전문과 정책 설정을 제공했다. 평가 시나리오, 정답 출력과 모범 구현은 모델 입력에서 제외했다. 같은 150개 시나리오를 세 번 채점했으며 시나리오 유형은 15종이다.

예약 취소 시드 43은 24시간·10분·시작 정각 규칙을 모두 받았지만, 함수가 10분 유예를 먼저 허용해서 시작 정각과 그 직후에도 취소를 허용했다. 오답 5개가 모두 이 우선순위에서 나왔다. 시드 17과 29는 시작 여부를 올바르게 처리해 40문항을 모두 맞혔다.

## 자원 배정 세부 채점

한 시나리오에서 사건 결과, 최종 상태, 알림 순서가 모두 일치하면 1점이다. 구성 요소별 수치는 그 구성 요소 전체가 일치한 시나리오 수다. 기존 채점기는 출력 스키마 검사를 먼저 시행하며, 실행 오류나 형식 오류가 있으면 세 요소 모두 오답으로 기록한다.

| --- | --- | --- | --- | --- |
| 17 | 0 | 0 | 0 | 60 |
| 29 | 0 | 0 | 0 | 142 |
| 43 | 0 | 0 | 0 | 10 |

시드 17의 제출은 재전송을 처리할 때 순회 중인 결과 목록에 다시 항목을 추가해, 원래의 일괄 채점이 중단됐다. 원래 생성한 코드를 보존하고 세 시드 모두 같은 방식으로 다시 채점했다. 시나리오별로 제출 소스의 Python 행 실행 100,000회를 한도로 적용했고, 한도 초과는 그 시나리오의 실행 오류로 기록했다. 동일한 격리 환경과 원래 채점 규칙을 사용했다. 이 조건에서 기준 구현은 150/150이었다.
