# 혼합 감시의 코드 지적을 편집기에 전달한 업로드 짝실험

2026년 11월 26일 · Qwen3.5-4B 메인 · Qwen·Gemma·Phi 혼합 감시 · 편집 시드 273

같은 초안·질문 세 개·회신 한 건·코드 지적 두 건으로 두 편집기를 각각 한 번 실행했다. **1회차는 12/20 → 20/20**이었다. 기존 정답 12개를 모두 보존했고, 기존 코드에서 반환값이 누락된 8개 입력을 모두 고쳤다. 새 코드의 20/20은 최종 제출까지 유지됐다. 1회차 문항별 비교 (로컬 보관 자료) · 최종 문항별 비교 (로컬 보관 자료)

| 업로드 공식 20문항 | 기존 편집 | 지적을 받은 조건식 편집 |
|---|---:|---:|
| 1회차 직후 | 12 | 20 |
| 2회차 직후 | 12 | 20 |
| 3회차 최종 | 12 | 20 |

두 조건의 1회차는 같은 가중치와 시드로 새로 실행했다. 기존 편집 결과는 당시 1회차 제출과 바이트 단위로 같았다. 2·3회차의 기존 열은 보관한 원래 혼합 감시 기록이다. 새 열은 1회차를 독립 제출로 고정한 뒤, 정답이 늘고 기존 정답 손실이 없을 때만 같은 감시자 순환 배정과 자연어 정책 카드로 이어간 실행이다. 점수와 평가 입력은 모델 요청에 포함하지 않았다. 실험 설계 (로컬 보관 자료) · 두 편집기가 공유한 원본 입력 (로컬 보관 자료)

## 8건이 고쳐진 이유

기존 코드에서는 `return True`가 `size_bytes > 16` 분기의 `return False` 바로 아래에 있었다. 1·2·4·8·12·14·15·16바이트는 함수 끝에 도달해 모두 `None`을 반환했다. 새 편집기는 공개 명세와 담당자 회신을 근거로 참인 조건과 거짓인 조건을 각각 제안했다. 실제 참 조건은 `size_bytes > 0 and size_bytes < 16 or size_bytes == 16`이었다. 두 식이 정수 전체를 나누는지 확인한 편집기가 원래의 두 미구현 위치에 반환문을 넣었다. 8개 입력 모두 `True`로 바뀌었다. 기존 코드 (로컬 보관 자료) · 수정 코드 (로컬 보관 자료) · 모델이 실제로 낸 조건식 (로컬 보관 자료)

연구자가 실행 전에 두 지적이 가리키는 미구현 위치를 확인하고, 공개 명세의 일반 규칙과 회신의 상한·등호·빈 파일 정책을 대조했다. 이 근거가 확인된 입력 한 건에만 새 편집 경로를 열었다. 조건식 작성 호출에는 기존 초안과 지적 두 건을 원문 그대로 전달했다. 연구자의 대응표는 모델에 제공하지 않았다. 이 방법으로 검증한 대상은 **경로를 열어 주었을 때 작성기가 이미 받은 답을 구현하는지**다. 새로운 지적의 범위와 근거를 자동으로 판별하는 성능은 별도 연구 질문이다. 사전 적용 범위와 근거 (로컬 보관 자료)

2·3회차에는 감시와 편집을 실제로 수행했다. 후속 편집 제안 네 건 중 2회차 두 건은 교체할 원문을 정확히 찾지 못해 거절됐다. 3회차는 변경 범위와 코드 구문 검사에서 각각 거절됐다. 그 결과 최종 파일은 1회차의 20/20 코드와 바이트 단위로 같았다. 2회차 원기록 (로컬 보관 자료) · 3회차 원기록 (로컬 보관 자료) · 최종 코드 (로컬 보관 자료)

## 비용

1회차 **편집만** 세면 기존 1,845토큰, 새 방식 1,662토큰이었다. 기존은 편집 제안과 형식 재시도, 새 방식은 동작 해석과 조건식 작성으로 각각 두 번 호출했다. 공통 초안·첫 회차 감시 세 건까지 포함해 세 회차 전체를 합산하면 기존 **14,109토큰**, 새 방식 **13,023토큰**이었다. 양쪽 모두 16회 호출이며, 공통 요청은 각 조건의 비용에 한 번씩 포함했다. 이 수치는 한 과제와 한 시드에서 관찰한 값이다.
