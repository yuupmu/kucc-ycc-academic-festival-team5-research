# 감시 의견 전달과 정각 오류 수정 검증

기존 실험에서 Qwen3 감시자 2는 정정 시간이 이용 시작 후에도 적용되는지 물었다. 담당자는 시작 순간부터 거부한다고 답했다. 메인의 첫 수정은 예약 후 300초, 시작까지 0초인 취소를 허용했다. 이 사례에서 의견의 전달과 코드의 수정을 따로 확인했다. 기존 실행 (로컬 보관 자료)

## 같은 제출에서 시작한 로컬 실행

Qwen3-8B Q4_K_M, 추론 모드 끔, 시드 43, 온도 0.3, 출력 상한 1,500토큰을 유지했다. 기존 세 감시 의견을 다시 사용했다. 종전에 한 문단으로 기록된 담당자 답을 질문 내용에 따라 R1에는 10분 정정 규칙, R2에는 시작 순간부터 거부한다는 규칙으로 연결했다. R3은 비워 두었다. 모델이 공통으로 낸 첫 제출은 39/40이었고 두 수정 방식에 정확히 같은 제출을 사용했다.

| 첫 제출 이후 | 추가 호출 | 추가 입력 / 출력 토큰 | 추가 모델 응답 시간 | 정각 결과 | 최종 점수 |
|---|---:|---:|---:|---|---:|
| 실패 결과를 나열하고 재수정 요청 | 5 | 7,865 / 950 | 37.77초 | 허용, 미해결 | 39/40 |
| 담당자 답 옆에 실패한 함수 호출·기대값·실제값을 놓고 잘못된 분기 수정을 요청 | 1 | 1,664 / 442 | 21.64초 | 거부, 검사 통과 | 40/40 |

공통 첫 제출 비용은 입력 1,293토큰, 출력 190토큰, 10.28초다. 표의 시간은 추가 모델 호출의 응답 시간 합이다. 수정 여부는 담당자가 확인한 예로만 판정했다. 40문항 점수는 수정 절차가 끝난 뒤에 계산했다. 일반 재수정 원문 (로컬 보관 자료) · 최종 방식 원문 (로컬 보관 자료)

최종 코드에서 시작까지 남은 시간의 조건이 `< 0`에서 `<= 0`으로 바뀌었다. 담당자 답에서 나온 서로 다른 입력 5개가 모두 통과했다. 초기 답과 R1에 같은 규칙이 있어서 원문 기록의 검사 행은 8개다. 첫 진단 실행에서는 10분이 지난 사례의 거부도 검사했다. 최종 방식에서는 정정 규칙만 확인한 답으로 일반 마감까지 추정하지 않도록 이 검사를 제외했다. 양쪽에서 실제로 실패해 모델에 전달된 입력은 같은 정각 사례 한 개였다.

## 전달 경로 검증

- 14B 시드 43의 질문 칸 세 개는 모두 비어 있었다. 과거 응답을 새 전달 경로에 넣어 “이 부분을 확인해주세요”가 담긴 의견 원문과 그 의견에 연결한 답이 메인 입력에 함께 남는지 확인했다. 14B 원문 (로컬 보관 자료)
- 7B 시드 43의 세 감시자는 문제를 보고하지 않았다. 세 답을 비워 둔 경우 추가 검사와 재수정 호출은 모두 0건이었다. 7B 원문 (로컬 보관 자료)
- 웹 실행에서는 전 버전의 감시자가 최신 버전 감시자보다 늦게 돌아오는 상황을 시험했다. 늦은 질문이 담당자에게 도달했고, 그 답과 원문을 받은 메인이 수정한 코드에서 정각 검사가 통과한 뒤 완료됐다. [웹 회귀 검사](../../tests/test_completion_gate.py)

이번 실모델 결과는 과거 실패 사례 한 건에 대한 재현이다. B와 C의 평균 효과를 추정하려면 조건별 첫 수정 점수와 추가 수정을 포함한 최종 점수를 각각 비교해야 한다.
