# 학술제 프로젝트

작업 에이전트 3개 + 감시 에이전트 3개 구조의 최소 웹 화면입니다. 흰 배경과 기본 입력창으로 구성했습니다.

## 실행

이 폴더에서 `python3 serve.py`를 실행한 뒤 브라우저에서 http://127.0.0.1:8000 을 엽니다. Mac에서는 `start.command`를 실행할 수도 있습니다. 다른 프로그램이 8000번 포트를 사용 중이면 `python3 serve.py --port 8001`을 실행합니다.

화면은 `web/index.html`을 직접 열어도 동작합니다. 설치할 외부 패키지는 없습니다.

## 구성

```text
학술제 프로젝트/
├── web/
│   ├── index.html       화면 구조
│   ├── styles.css       흰 배경의 최소 스타일
│   ├── app.js           화면과 분기 연결
│   └── branch-runner.js 독립 감시 분기 실행·응답·통합
├── serve.py             로컬 화면 서버
├── start.command        Mac 실행 파일
└── reservation_benchmark/
    ├── agent/           문제와 제출용 함수
    ├── evaluator/       정책·정답·100문항·정답 구현
    ├── score.py         Python 자동 채점기
    ├── build_cases.py   사례 재생성
    ├── tests/           채점기 검증
    └── reports/         채점 결과
```

## 현재 구현 범위

- 과제·작업 모델 설정 화면과 감시자별 컨셉·모델·판단 지침 직접 입력
- 감시자 3개의 독립 분기: 각각 상태·질문·답변·기록을 보관하고 병렬 시작
- 한 분기에 답하면 그 분기만 진행. 나머지는 답변 대기를 유지
- 세 분기가 모두 완료된 후에만 응답을 모아 표시
- 분기별 입력 지침·질문·답변·결과가 포함된 JSON 내려받기
- 작업 A/B/C 상태 표와 분기별 인간 응답의 **로컬 데모**
- 데모 중단·초기화·기록 JSON 내려받기
- 실제 점수가 연결될 결과 영역
- 별도 실행 가능한 기존 Python 벤치마크

실제 GPT 호출, 작업 에이전트 실행, 코드 생성, 웹에서 Python 채점 실행은 아직 연결하지 않았습니다. 감시 분기들은 서로 다른 실행 컨텍스트와 응답 대기를 갖지만 질문은 사전 작성된 고정 예시입니다. 컨셉·지침·모델은 각 분기 입력으로 보관되며 질문 생성에는 사용되지 않습니다. 통합은 응답을 모으는 단계이며 의미 분석이나 충돌 해결을 수행하지 않습니다. 화면의 데모 기록은 메모리에만 보관하므로 새로고침 시 사라집니다. 결과 점수는 비워 둡니다.

웹 서버는 `web/`만 제공하고 평가 정답은 제공하지 않습니다. 실제 에이전트를 연결할 때는 `evaluator/`를 에이전트가 읽지 못하는 별도 환경에서 실행해야 합니다.

## 기존 채점기 실행

```sh
cd reservation_benchmark
python3 score.py evaluator/reference.py --output reports/reference.json
python3 score.py agent/solution.py --output reports/submission.json
```

정답 구현은 100점, 미구현 제출 틀은 0점입니다. 자세한 규칙과 실험 가정은 `reservation_benchmark/README.md`를 확인하세요.

## 다음 연결 지점

1. 백엔드 실행 관리: 작업 배분·상태·질문·응답을 관리.
2. 모델 호출: 작업 3개와 감시 3개를 실제 모델 호출에 연결. 현재 3컨셉은 감시자 3명에 각각 대응하며 9명을 실행하지 않습니다.
3. 평가 실행: 제출 결과를 별도 환경의 채점기로 실행하고 결과를 화면에 전달.

감시 분기는 각각 Promise로 실행되며 독립적으로 답변을 기다립니다. 검토·후속 처리만 타이머로 모사합니다. 이후 각 분기의 고정 질문 생성을 모델 호출로 교체하면 됩니다.

분기 독립성·중단·통합·화면 연결 검증: `node --test tests/web-runtime.test.cjs`.
