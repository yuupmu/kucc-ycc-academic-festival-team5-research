# 04. 작업·검토·인간 답변은 어떻게 이어지는가?

## 이 슬라이드가 필요한 이유

워크플로우라는 단어 대신 구체적인 입력과 출력의 순서를 보여줍니다. 인간이 어디에서 개입하는지, 답이 어떤 경로로 코드에 반영되는지 설명합니다.

## 슬라이드 본문

### 1. 계획과 코드 한 버전을 검토합니다

메인이 계획이나 코드를 제출하면 검토자 3개가 같은 상태를 받습니다. 각 검토자는 계속 진행, 추가 검사, 사람에게 질문 중 필요한 행동을 제안합니다.

### 2. 필요한 질문을 사람에게 보여줍니다

예를 들어 “취소 마감이 휴무일이면 언제로 옮길까요?”라고 묻습니다. 사람이 “앞선 영업일 18시”라고 답하면 그 내용을 공유 기록에 넣습니다.

### 3. 답을 반영해 수정하고 다시 확인합니다

메인은 새 답변과 검사 결과를 보고 코드를 고칩니다. 검토도 다시 진행합니다. 작업을 완료한 뒤 사용자가 별도의 정답 세트로 최종 점수를 확인합니다.

**핵심 메시지:** 검토는 계획·코드 제출 시점마다 진행하며, 모델의 내부 생각을 실시간으로 읽지는 않습니다.

## 발표할 때 풀어서 설명하기

흐름은 작성, 검토, 질문, 답변, 수정의 반복입니다. 메인이 처음부터 코드를 모두 완성해야만 감시가 시작되는 것은 아닙니다. 계획이 나왔을 때도 검토하고, 코드가 한 버전 나올 때마다 다시 검토합니다. 검토자 중 한 명이 질문을 제출하면 다른 검토자가 끝날 때까지 기다리지 않고 사람에게 보여줄 수 있습니다. 답변은 기록에 저장되어 다음 메인 호출과 검토 호출에 전달됩니다. 마지막에는 모델이 만든 자체 검사와 별도로 준비한 정답 세트로 평가합니다. 이렇게 해야 모델이 스스로 정한 검사만 통과한 결과를 최종 성공으로 오해하지 않을 수 있습니다.

## 해석할 때 주의할 점

모델이 “답변을 반영했다”고 보고한 사실과 실제로 올바르게 반영한 사실은 다릅니다. 현재 구조는 보고와 검사 결과를 기록하며, 의미적으로 완벽한 반영을 보장하지 않습니다.

## 다음 슬라이드 연결

이 흐름이 제대로 작동하는지 보기 위해 처음에는 단순한 문제를 쓰고, 이후 여러 사건이 연결되는 문제로 확장했습니다.

## 근거

[로컬 구현·실험 기록](<../reports/multi-agent-lab_구현_실험_기록_2026-11-10.md>) 및 사용자가 제시한 연구 동기·후속 연구 방향. 후속 설계는 아직 수행하지 않은 제안입니다.
