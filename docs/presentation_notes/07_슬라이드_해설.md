# 07. 90점과 실행 실패는 무엇을 알려주었는가?

## 이 슬라이드가 필요한 이유

실패 사례를 통해 왜 로그와 인간 응답 통제가 중요한지 설명합니다. 시스템이 단순히 정답 점수를 출력하는 수준을 넘어 실패 원인을 분류할 수 있어야 다음 연구가 가능합니다.

## 슬라이드 본문

### 90점: 인간 답변과 정답 규칙이 달랐습니다

검토자는 추가 휴일이 있는지 물었고, 사람은 “없다”고 답했습니다. 하지만 채점기는 추가 휴일 2개를 전제하여 관련 문제 10개가 틀렸습니다.

### 다른 실행에서는 프로그램 운영 문제가 있었습니다

사용할 수 없는 라이브러리, 모델 접근 오류, 잘못된 응답 형식 때문에 멈췄습니다. 이런 실패를 모두 모델의 문제 해결 능력 부족으로 해석할 수는 없습니다.

### 그래서 복구와 기록 기능을 보강했습니다

코드 오류를 다시 수정할 자료로 전달하고, 답변과 이전 코드를 보존했습니다. 무엇이 실패했는지 상세하게 기록하고 중단 후 이어서 실행하도록 했습니다.

**핵심 메시지:** 점수를 해석할 때는 모델의 코드, 사람이 준 정보, 실행 환경을 함께 살펴봐야 합니다.

## 발표할 때 풀어서 설명하기

90점 실행에서는 감시자가 필요한 질문을 놓친 것이 아닙니다. 추가 휴일을 물었지만 사람이 없다고 답했습니다. 그런데 정답에는 두 날짜가 추가 휴일로 들어 있었습니다. 따라서 이 점수 차이는 인간에게 받은 정보와 채점 기준의 충돌을 반영합니다. 또 다른 실행에서는 모델이 쓴 코드가 허용되지 않은 외부 라이브러리를 사용하거나, 요청한 형식에 맞지 않는 검토 응답을 보내면서 실행이 멈췄습니다. 이런 문제를 겪고 나서 오류가 나도 사람의 답변을 입력할 수 있게 하고, 코드 수정의 재료로 오류를 돌려주며, 나중에 원인을 볼 수 있도록 기록을 자세히 남겼습니다.

## 해석할 때 주의할 점

과거 일부 형식 오류는 실패 응답 원문을 저장하지 않아 정확한 조건을 복원할 수 없습니다. 추정 원인을 확정된 사실처럼 말하지 않습니다.

## 다음 슬라이드 연결

실행 오류를 고치더라도, 좋은 결과가 모두 만점이라면 구조의 차이를 어떻게 측정할지라는 문제가 남습니다.
